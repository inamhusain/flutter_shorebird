A code push tool for Flutter.

It sends Dart code fixes straight to users' phones, with no new store build and no store review.

Release
The store build.

The .aab or .ipa you upload. Shorebird keeps a copy of its Dart code.

Patch
The fix.

New Dart code for one exact release version, downloaded over the air.

Fast

No store review. The patch reaches users within minutes.

Automatic

Users don't update from the store. The app updates itself.

Store-safe

Only Dart code changes, never native code.

00 · How it works
  • Releaseshorebird release builds the app and saves its Dart code.
  • StoreUpload the .aab / .ipa. The store reviews it once.
  • Patchshorebird patch diffs your new Dart against the release.
  • CloudOn launch, the app asks: "any patch for my version?"
  • DeviceDownloads in the background and applies when the app is restarted.
01
Build the release
CodeStorePatchCloudPhone

Under the hood.

Shorebird builds your app with its own fork of the Flutter engine, which includes an updater.

Android
Full speed.

Patched Dart runs as AOT machine code.

iOS
Only what changed.

Changed functions run in a custom interpreter. Everything else runs at full AOT speed. Real devices only, not Simulators.

Versioning
Exact match.

A patch reaches only its release, for example 1.0.0+1. The old patch is deleted after a new one boots fine.

01 · Create a release

    
Version + build number.

    
Every release is identified by 1.0.0+1, which is the version and the build number together. Patches only reach that exact pair.

    

      
Option A · pubspec.yaml
Default.

        
version: 1.0.0+1
# 1.0.0 = build-name, 1 = build number

      
Option B · command line
Overrides pubspec.

        
shorebird release android \
  --build-name=1.0.0 --build-number=1

      
Store rule
Bump the build number for every upload, because the stores reject duplicates.

      
Other flutter build args
Put them after --, for example -- --dart-define="foo=bar". In PowerShell, quote it as '--'.

    

  






  

    
01 · Create a release

    
Pin your Flutter version.

    
shorebird flutter versions list                       # supported versions, ✓ = default
shorebird --version                                   # also shows the current Flutter version
shorebird release android --flutter-version=3.47.7    # pin a version
shorebird release android --flutter-version=fvm       # use the project's .fvmrc
shorebird release android --flutter-version=system    # use the flutter on your PATH

    

      
Default
The Flutter version bundled with Shorebird, which is the latest stable.

      
Release only
Only release takes the flag. Patches always use the release's Flutter version.

      
Pick a real one
3.47.7 is the docs' example. Choose a version from the list.

Ship it.

    
Illustrative output

    
    
# Android: .aab (default), upload to Play Console

shorebird release android --flavor=prod --target=lib/main_prod.dart --build-name=1.0.0 --build-number=1

# Check
shorebird releases list
shorebird releases info --release-version 1.0.0+1

  







  

    
02 · Create a patch

    
Fix in Dart. Patch.

    
Illustrative output

    
    
# build and validate only, no upload
shorebird patch android --release-version=1.0.0+1 --track=staging --dry-run

shorebird patch android --release-version=1.0.0+1 --track=staging
shorebird patch ios     --release-version=1.0.0+1 --track=staging

# both at once
shorebird patch --platforms=android,ios --release-version=1.0.0+1 --track=staging

    

      
--release-version
Without it, the CLI uses the version from the compiled build. latest targets the most recently updated release.

      
--track
Defaults to stable (all users). Use staging to review the patch first.

      
Flavors
Use the same flag as the release, --flavor=prod.

      
Override checks
--allow-asset-diffs and --allow-native-diffs publish anyway. The docs mark both as not recommended.

03 · Review

    
Test it on staging first.

    
shorebird patches list --release-version 1.0.0+1      # patch number and its track

# app_id is in shorebird.yaml (one per flavor)
shorebird preview --app-id <your-app-id> --release-version 1.0.0+1 --track staging --platform android
shorebird preview --app-id <your-app-id> --release-version 1.0.0+1 --track staging --platform ios

    

      
Install
Installs the release on a device and points it at staging. --app-id picks the app (or flavor). Copy it from shorebird.yaml.

      
Relaunch twice
The patch downloads in the background, so kill and reopen the app twice to see it.

      
Real iPhone
iOS patches don't run on Simulators.

      
Review checklist

        
    
          
  • The bug is fixed
  • No new crashes on the main flows
  • It works on Android and iOS
  • Patch size and installs look right in the console

Console · promote
Open the release details page, choose Change Track, then stable. The CLI flags need 1.6.128 or newer.

      
Console · roll back
Click the three-dot menu on the patch, then Rollback. Devices go back to the previous patch or the base release on their next launch.

      
Skip staging
shorebird patch android with no --track goes straight to stable.

05 · With the update gate

        

          
Check first.
Before the real app shows, a loading screen asks Shorebird for a new patch. The timeout is 5 seconds.

          
Download it.
If there's a new patch, download it right there. Patches are usually a few KB, and the timeout is 30 seconds.

          
Restart for them.
Android restarts itself, so there's no restart for the user to do. On iOS and desktop, the app asks the user to close and reopen it, because Apple doesn't let apps restart themselves.

          
Fixed. First launch.
The user never sees the bug. No patch, no internet or a timeout? The app opens normally. The user is never blocked.

05 · Manual update

    
Two files. Then the gate.

    

      
Step 1 · shorebird.yaml
Turn off automatic updates so our code decides when to check.

        
app_id: your-app-id
auto_update: false

      
Step 2 · pubspec.yaml
The updater API and a restart helper for Android.

        
dependencies:
  shorebird_code_push: ^2.0.7
  restart_app: ^1.10.2

      
Important
The gate needs its own store release, because auto_update lives in shorebird.yaml and can't be changed by a patch.

    

  






  

    
05 · Step 3

    
The update gate.

    
Replace main() and rename MyRealApp to your app widget.

    
lib/main.dart
import 'dart:async';
import 'dart:io';
import 'package:flutter/material.dart';
import 'package:shorebird_code_push/shorebird_code_push.dart';
import 'package:restart_app/restart_app.dart';

void main() => runApp(const UpdateGate());

class UpdateGate extends StatefulWidget {
  const UpdateGate({super.key});
  @override
  State<UpdateGate> createState() => _UpdateGateState();
}

class _UpdateGateState extends State<UpdateGate> {
  final _updater = ShorebirdUpdater();
  String _message = 'Checking for updates...';
  bool _ready = false;

  @override
  void initState() {
    super.initState();
    _checkAndApply();
  }

  Future<void> _checkAndApply() async {
    // Shorebird only works in release builds made with Shorebird
    if (!_updater.isAvailable) {
      setState(() => _ready = true);
      return;
    }
    try {
      final status = await _updater.checkForUpdate().timeout(const Duration(seconds: 5));
      if (status == UpdateStatus.outdated) {
        setState(() => _message = 'Downloading update...');
        await _updater.update().timeout(const Duration(seconds: 30));
        _restart();
        return;
      }
      if (status == UpdateStatus.restartRequired) {
        // Patch was downloaded before. Apply it now.
        _restart();
        return;
      }
    } catch (_) {
      // No internet, timeout or error: do not block the user
    }
    setState(() => _ready = true);
  }

  void _restart() {
    if (Platform.isAndroid) {
      setState(() => _message = 'Applying update...');
      Restart.restartApp();
    } else {
      // iOS and desktop: the app cannot restart itself
      setState(() => _message = 'Update installed. Please close and reopen the app.');
    }
  }

  @override
  Widget build(BuildContext context) {
    if (_ready) return const MyRealApp();
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      home: Scaffold(
        body: Center(
          child: Column(
            mainAxisSize: MainAxisSize.min,
            children: [
              const CircularProgressIndicator(),
              const SizedBox(height: 16),
              Text(_message, textAlign: TextAlign.center),
            ],
          ),
        ),
      ),
    );
  }
}
